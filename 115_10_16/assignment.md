# 第三週作業：火星探測車互動任務

完成課堂的 `RoverMission.java`，讓使用者選擇探索、掃描、充電或返回，並整理測試與 AI 建議的判斷紀錄。延續原有專案，不必從空白檔重寫。

截止時間與繳交平台：依教師公告。以下日期目錄請替換成實際上課日期。

## 1. 要完成什麼？

從 [starter/RoverMission.java](starter/RoverMission.java) 開始，完成 D1、D2、D3。初始能源 20、樣本 0、行動次數 0，目標至少 5 份樣本。

| 指令 | 必須實現的規則 |
|---|---|
| 1 探索 | 能源至少 6 才能扣 6、取得 2 份樣本，行動次數加 1。 |
| 2 掃描 | 能源至少 2 才能扣 2、取得 1 份樣本，行動次數加 1。 |
| 3 充電 | 未滿 20 才增加 5 格，超過時設為 20，行動次數加 1。 |
| 0 返回 | 結束任務，不扣能源、不增加行動次數。 |
| 其他整數 | 顯示無效指令，狀態不變。 |

能源不足或已滿電的行動要拒絕，不能給樣本或計次。保留既有輸入、顯示、case 0、default 與迴圈骨架；能源為 0、樣本達標或主動返回時結束。若同時耗盡能源且達標，優先顯示 SUCCESS。

輸入限定為 Java int 範圍內的整數。GUI、陣列、集合、隨機事件與完整例外處理不在本週必做範圍。

## 2. 必做測試與紀錄

每列重新啟動程式，從預設狀態開始，在 [student_lab.md](student_lab.md) D 記錄實際結果：

| 指令序列 | 最終 energy／samples／actionCount | 結果 |
|---|---|---|
| 0 | 20／0／0 | RETURNED |
| 1、1、2 | 6／5／3 | SUCCESS |
| 2、2、2、2、2 | 10／5／5 | SUCCESS |
| 3、9、0 | 20／0／0 | RETURNED |

另完成講義 D 三筆教師固定狀態示範的預測與觀察紀錄：5／0、6／0、2／4。**這三筆由教師操作，學生填寫觀察結果；不要求每位學生另寫測試入口。** 缺席或尚未觀察者先註明待補，再依教師安排補看或自行複驗。

`FixedStateMission.java` 是教師提供的測試工具，並非另一份必寫作業。若自行使用，可將它與完成的 `RoverMission.java` 放在同一個 src 內；兩個 main 分別是一般任務與固定狀態測試的入口。自行複驗後，繳交版的一般入口仍保持能源 20、樣本 0。

## 3. AI 除錯三選一

從講義 D 的三種模擬錯誤中選一種：條件寫成 `> 6`、移除 break、每輪重設 samples。先保存自己的原版，再於測試副本重現錯誤，最後恢復正確程式。

繳交時須有以下三筆證據；直接填在講義 D，不另做重複報告：

1. 一筆反例：預測、修改前結果、最小修正與修正後結果。
2. 修正後的一般成功案例：預設狀態輸入五次 2。
3. 修正後的返回／拒絕案例：預設狀態輸入 3、9、0。

課堂未完成的測試於課後補齊。可以只用教師模擬建議，不要求 AI 帳號；在四欄 AI 紀錄中註明即可。若使用真實 AI，記錄自己的提問與採納／拒絕理由。

## 5. 執行、保存與繳交

在 `java-03` 目錄執行；編譯成功後再執行程式：

```powershell
javac --release 21 -encoding UTF-8 -d out src/*.java
java -cp out RoverMission
```

完成後 commit、push，核對 GitHub 的當日程式與紀錄，再向教師指定平台繳交 **repo 網址、作業目錄及最終 commit**。在另一個新位置 clone，重新編譯並執行 1、1、2，將版本與結果記入講義 F；課堂時間不足可課後完成，未做不可標成通過。

## 6. 驗收標準

- 三個行動符合成本、效果與拒絕條件，計次與停止順序正確。

- 檔案完整，教師能依 README 執行，GitHub 版本與繳交紀錄一致。
